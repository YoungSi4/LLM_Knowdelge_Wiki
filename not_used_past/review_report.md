# Yacht Game Code Review Report

## 1. 개요
- **대상 파일**: `yacht_game.py`
- **리뷰 목적**: 주사위 정렬(sort) 로직이 고정 인덱스(keep_indices) 시스템에 미치는 영향 분석 및 잠재적 버그 식별.

## 2. 주요 분석 내용

### 2.1 주사위 데이터 구조 및 관리
- `self.dice`: 5개의 정수 리스트로 주사위 눈을 저장함.
- `self.keep_status`: 5개의 불리언 리스트로 각 인덱스별 고정 상태를 관리함.
- `roll_dice()`: `self.keep_status[i]`가 `False`인 인덱스의 `self.dice[i]`만 갱신함.

### 2.2 주사위 정렬(Sort)의 영향
- **현재 구현 상태**: `self.dice` 리스트 자체를 정렬(`sort()`)하는 로직은 존재하지 않음. 
- **부분적 활용**: `calculate_scores` 메서드 내부에서 스트레이트 판정을 위해 `unique_dice = sorted(list(set(dice)))`와 같이 **복사본**을 정렬하여 사용 중임. 이는 원본 `self.dice`의 순서를 변경하지 않으므로 안전함.
- **잠재적 위험성**: 만약 사용자 편의를 위해 `display_board` 호출 전이나 `roll_dice` 직후에 `self.dice.sort()`를 수행하게 될 경우, 기존의 `self.keep_status` 인덱스와 주사위 값의 매칭이 깨지게 됨.
    - 예: 주사위가 `[5, 1, 3]`이고 1번(값 5)을 고정했을 때, 정렬하여 `[1, 3, 5]`가 되면 고정 상태는 여전히 1번 인덱스를 가리키므로 값 1이 고정되는 오류 발생.

## 3. 상세 체크리스트

| 항목 | 상태 | 비고 |
| :--- | :---: | :--- |
| `self.dice` 인덱스 고정 여부 | **안전** | 원본 리스트가 정렬되지 않음. |
| `calculate_scores` 정렬 방식 | **안전** | `sorted()` 함수를 사용하여 새 리스트 생성. |
| `keep_status` 업데이트 방식 | **정상** | 사용자 입력(1-5)을 0-based 인덱스로 변환하여 관리. |
| UI 가독성을 위한 정렬 요구사항 | **미반영** | 현재 무작위 순서로 출력됨. |

## 4. 권장 개선 사항

1. **시각적 정렬 도입 시 주의**: 만약 주사위를 정렬하여 보여주고 싶다면, `self.dice` 자체를 정렬하지 말고 `display_board` 내부에서만 정렬된 복사본을 출력하거나, 정렬 시 `keep_status`도 동일한 규칙으로 재배치(Shuffle)해야 함.
2. **인덱스 혼동 방지**: 현재는 주사위 번호(1-5)가 리스트의 물리적 위치와 일치함. 주사위를 정렬할 경우 사용자에게 보여지는 번호와 내부 인덱스 간의 매핑 로직이 추가로 필요함.

## 5. 결론
현재 `yacht_game.py`의 구현은 주사위 정렬로 인한 인덱스 꼬임 문제로부터 **안전**합니다. 주사위 판정 시에만 별도의 정렬된 세트를 활용하므로, 주사위 고정(Keep) 기능은 의도한 대로 동작합니다. 

단, 향후 UI 개선을 위해 주사위 출력 순서를 변경할 계획이 있다면 반드시 인덱스 매핑 로직을 재검토해야 합니다.
