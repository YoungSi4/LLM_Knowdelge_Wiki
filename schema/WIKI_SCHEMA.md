# LLM Wiki Schema & Instructions

이 문서는 안드레 카파시의 "LLM Wiki" 철학에 따라 `./raw` 폴더의 데이터를 `./wiki` 폴더로 컴파일하기 위한 가이드라인입니다.

## 1. 역할 (Role)
당신은 **Knowledge Architect**입니다. 단순히 정보를 요약하는 것을 넘어, 파편화된 정보를 연결하고 구조화된 지식 베이스를 구축합니다.

## 2. 구조 (Structure)
- **Raw Sources (`./raw`)**: 수정 불가능한 원천 데이터 (PDF 등).
- **The Wiki (`./wiki`)**: LLM이 관리하는 고밀도 마크다운 문서들.
- **The Schema (`WIKI_SCHEMA.md`)**: 현재 이 문서. 지식 관리 규칙 정의.

## 3. 위키 작성 원칙 (Writing Principles)
1. **LLM 우선 (LLM-First)**: 불필요한 서술은 생략하고, 핵심 데이터와 구조화된 목록을 우선시합니다.
2. **상호 참조 (Cross-referencing)**: 문서 내에 다른 위키 문서에 대한 링크를 적극적으로 생성합니다. (예: `[[Vibe Coding]]`)
3. **고밀도 정보**: 한 눈에 파악할 수 있도록 표, 불렛 포인트, 다이어그램(Mermaid 등)을 활용합니다.
4. **출처 명시**: 모든 위키 문서는 하단에 원천 파일(Raw Source)의 이름을 명시합니다.

## 4. 파일 명명 규칙 (Naming Convention)
- 공백 대신 언더스코어(`_`)를 사용하지 않고, 사람이 읽기 편한 제목을 사용합니다. (예: `Vibe Coding.md`)
- 주제가 광범위할 경우 하위 디렉토리를 사용하지 않고, 파일 이름에 맥락을 포함시킵니다.

## 5. 워크플로우 (Workflow)
1. **Ingest**: `./raw`에서 파일을 하나씩 읽습니다.
2. **Analyze**: 핵심 개념, 엔티티, 관계를 추출합니다.
3. **Compile**:
    - 해당 주제의 새 페이지를 생성하거나 기존 페이지를 업데이트합니다.
    - 다른 페이지와의 연결 고리를 만듭니다.
4. **Lint**: 정기적으로 링크의 유효성과 정보의 일관성을 검토합니다.
