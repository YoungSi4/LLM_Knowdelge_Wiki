# Loop and Hooks

## 개요
에이전트의 생애 주기(Life Cycle) 내 특정 시점에서 자동으로 동작을 실행하는 **Hook**과, 정기적 또는 조건부로 작업을 반복 수행하는 **Loop**에 대해 다룹니다.

## 훅 (Hook)
- **정의**: 에이전트의 동작 과정 중 특정 이벤트가 발생할 때 자동으로 실행되는 스크립트 또는 로직.
- **주적**: 확률적으로 동작하는 LLM 에이전트에게 결정론적(Deterministic)인 제약이나 기능을 부여하여 신뢰성을 높이는 것.

### 1. 주요 이벤트 시점 (Events)
| 이벤트 | 실행 시점 | 활용 사례 |
| :--- | :--- | :--- |
| **UserPromptSubmit** | 사용자가 프롬프트를 제출했을 때 | 지식 베이스 사전 체크, 추가 프롬프트 주입 |
| **PreToolUse** | 도구 사용 직전 | 위험 명령어 필터링, 권한 사전 검토 |
| **PostToolUse** | 도구 실행 직후 | 도구 실행 결과 기록 (Log), 상태 업데이트 |
| **Stop** | 한 턴(Turn)이 끝나려 할 때 | 작업 완료 보고, 결과 유효성 최종 확인 |
| **SessionStart** | 세션 시작 또는 재개 시 | 환경 초기화, 이전 저널 읽기 |

### 2. 주요 사용 패턴
- **자동 검증**: 코드 작성 후 `Stop` 훅을 통해 테스트 스크립트를 자동 실행.
- **로그 기록**: `PostToolUse` 시점에 어떤 도구를 사용했는지 외부 DB나 파일에 기록.
- **지식 연동**: 사용자의 질문이 들어오면 `UserPromptSubmit` 시점에 관련 문서를 검색하여 컨텍스트에 포함.

## 루프 (Loop) 및 자동화
- **정의**: 스케줄러를 통해 일정 시간 간격으로 에이전트를 호출하거나, 특정 조건이 만족될 때까지 작업을 지속하는 행위.
- **주의사항**:
    - **비용**: 지속적인 Read/Write 작업은 높은 API 비용을 발생시킴.
    - **권장 방식**: 단순 상태 체크(Status Checking) 위주로 구성하거나, 비용이 저렴한 로컬 모델(Ollama, vLLM 등)을 연동하여 활용.

## 하이브리드 전략
- **Action**: 고성능 상용 모델(Claude, Gemini 등)에게 복잡한 의사결정과 코드 작성을 맡김.
- **Monitoring/Simple Task**: 로컬 모델을 통해 루프를 돌며 상태를 감시하고, 필요 시 상용 모델을 호출.
